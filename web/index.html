The interface

A read-only glance at every engagement

One question per line: which engagements are live, what the wave is doing, which events just landed. The interface never invents a metric — an unknown count renders as an em-dash.

Tool calls

Every tool call is rendered, gated, parsed, event-sourced

Rule packs name bare binaries and argv templates. Nothing reaches a tool that the engagement cannot render, that the scope gate refuses, or that the OPSEC board is cooling down.

Render — placeholders come from engagement state

A rule's cmd template renders against facts the engagement holds. A rule it cannot render is never proposed; one that still reaches fire time is refused by the ACT gate, and the refusal is an event. motoko rules checks the whole corpus statically — no traffic, no LLM.

Gate — scope and OPSEC speak before the tool does

The scope gate is engine-side and fail-closed: label-boundary domain matching, per-IP CIDR checks, redirect-chain and certificate-SAN checks. Per-origin cooldowns and canary guards block pressure. Out-of-scope is a halt, not a pivot.

Dispatch — bare binaries, bounded fan-out

Tool values are bare names — a path is refused outright. Secrets travel as @env:NAME; argv never carries the value. Fan-out is bounded by registrable origin, category reservations and serial batches. Destructive edges wait for the operator.

Parse — output becomes evidence, chains become waves

Parsers turn tool output into observations with deterministic dedup keys. Producer keys feed the next rule's consumers; discovered facts reopen assets in the next wave. Duplicate evidence earns no discovery credit.

Research

Borrowed from institutions that grade assurance

RESEARCH.md surveys how military-grade programs are actually graded — assurance, provenance, adjudication — across 23 documented patterns, and derives an M1–M15 adoption roadmap from them. MOTOKO claims no such grade; it copies the parts a stdlib Python orchestrator can afford.

US programs

CISA · ScubaGear
The unified verdict record — every check names its tool call, its normative strength, and declares what it cannot evaluate instead of dropping it
NIST · OSCAL + SP 800-115
Assessment results as a standard artifact; authorization as a data structure (ROE-as-data, authorized hours and source locations included)
DARPA · CGC + AIxCC
Put the gates on the API, not around the agent — it posts artifacts, never reaches the target; and never trust an agent's self-report: rescore from the event log
NSA · nsacyber
Every prose discipline ships with a machine-checkable detector; guidance and runnable detectors live in one repository
US Navy NAVSEA · STIG Manager
Content hash as rule identity — conclusions auto-inherit when the check content is unchanged
DoD Platform One · Big Bang
A doctor is a validity predicate, not a WARN list: name the minimal core set, missing one class means unhealthy
MITRE + Red Canary · Caldera, ART
Corpus discipline: typed inputs with defaults, prerequisite checks, cleanup commands

Allied programs

Canada CSE · AssemblyLine
A heuristic must be declared in the manifest before it can fire; the server recomputes scores and rejects unknown heuristics
France ANSSI · DFIR ORC
Two machine-readable run records: the Outline (execution context) and the Outcome (per-action results) — hash both the engine and every tool
Belgium · MISP
A closed vocabulary is one JSON file per term, schema-validated — adding a term is a data-only change
Australia ASD/ACSC · ISM as OSCAL
Profile over catalog: which subset applies at this assurance level is a data file, not hardcoded checks
UK NCSC
Guidance as machine-readable policy packs, sharded by threat model; parser contracts induced from a corpus
Filigran OpenCTI · TheHive Cortex
External legs on a contract: a closed connector type enum with scope registration, and self-describing parser manifests

M1–M15 adoption roadmap

  • Every rule action and parser output normalized to a verdict record; checks that cannot be evaluated are declared Not-Implemented, never silently dropped.

  • A standardized assessment artifact (OSCAL SAR), a machine-readable authorization object (ROE-as-data), and independent rescoring that never trusts an agent's self-report.

  • "Never allowed" patterns as data — every prose discipline paired with a detector.

Lawful public sources only. Leaked-tooling class material was not fetched and is not adopted — a technique that cannot prove its provenance is a liability. Per-project verdicts and license notes live in RESEARCH.md →

Trust

What ships. What waits. In writing.

Automation earns trust at its boundaries. The contract is larger than the engine — and MOTOKO says which half ships instead of blurring the line.

Where enforcement lives

Scope
Engine-side, fail-closed; refusals are first-class events
Interrupt
Operator-side. The destructive-edge circuit breaker is specified in the contract and enforced by the operator shell. The engine does not implement it yet.
Evidence
Engine-side: append-only events, SHA256 manifests, seal / --verify. Evidence storage is not encrypted.
Seat
The operator is not a node; the seat plugin is a thin control plane over the motoko CLI

Also operator-side today: bounded parallel fan-out and host-resource budgeting. motoko loop audits engineering changes (ROLLBACK/STOP verdicts) — separate from scan waves.

Finding states are explicit

  • Promotion is earned by hard evidence — a DOM confirmation or an out-of-band callback. Only validator events promote past triaged; a replay re-check caps out at reproduced.

  • Replay-observed; not yet the hard evidence a promotion needs.

  • A harness limitation parks the finding with a reason code instead of burning retries or terminating it — the evidence explains why.

  • Refused before it ran; recorded as a first-class event.

  • Queued work: dedup keys admit, the rule chain speaks, validators have not.

  • Closed without promotion; duplicates link through duplicate_of edges.

Nothing stamps verified_true; the verify beat is planned, not shipped. The full contract-versus-engine matrix lives in IMPLEMENTATION.md →

Getting started

From install to evidence in four steps

stdlib-only Python 3.11+, zero runtime dependencies. The first checks are read-only.

  1. 01

    Install the engine. One package, zero runtime dependencies — the motoko CLI comes with it.

    pip install ./engine
  2. 02

    Check the environment. Read-only — a passing doctor is not authorization to scan.

    motoko doctor
  3. 03

    Check the corpus. 40 rule packs, statically checked — no traffic, no LLM.

    motoko rules --report
  4. 04

    Initialize, run, digest. Replace the reserved example inputs with the approved scope. An exit code of zero does not mean every scanner succeeded.

    motoko init example --scope example.invalid --seed https://example.invalid/
    motoko run example --max-cycles 20 --wave-cycles 5 --max-waves 4
    motoko digest example

Bring your tools. Install the engine.

stdlib-only Python ≥ 3.11. The scanners and agents you already trust run under scope checks, OPSEC cooldowns, and an audit trail — one governed graph, one install. The scope gate is engine-side and fail-closed; the human interrupt is enforced by the operator shell.

Install the engine package; it provides the motoko console script.

pip install ./engine

Optional read-only terminal interface (Textual). motoko status and motoko watch stay stdlib.

pip install './engine[interface]'

Run without installing, straight from the source tree.

cd engine && python3 -m core --help
