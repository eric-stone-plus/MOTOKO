你是一名多智能体系统工程 + 强化学习机制设计专家。请为一个**迭代式代码审计/改进 loop** 设计收敛机制。核心问题：**这个 loop 到底跑几轮就够，如何自动判定"够了"然后停。**

## loop 现状

参与者：审计模型（多模型独立并行）→ 收束模型（去重排期）→ 落地 agent（改代码跑测试）→ 回到审计。

已知退化风险（无收敛判据时必然发生）：审计刷分无限产出问题、落地声称修复但没修或修 A 引入 B、越改越差无人察觉、无限烧 token、不知道这轮有没有进步。

## 请设计（中文，直接给方案，不客套）

1. **第几轮就够**：给经验上界（硬上界 + 软收敛点 + 依据，用缺陷清除衰减模型）。区分轮数（保险丝）与判据（可验证发现通量）。
2. **自动停止条件**：可编程判据，全部工具测量，零模型自评。
3. **奖励信号**：指标清单 + 权重 + 自动测量方法。
4. **审计发现真伪定价**：防刷分，独立验证管线 + 误报惩罚。
5. **退化检测与回滚**：判定条件 + 回滚锚点。
6. **资源预算兜底**：轮数/token/时间耗尽未收敛怎么办。
7. **可执行伪代码 + 状态机 + Schema**：每轮评估器，输入 → 输出 {reward, converged, rollback, action}。

要求：直接、可编码、字段级/伪代码级。只输出研究文档文本，不要读写文件、不要执行任何命令。
