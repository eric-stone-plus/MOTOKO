# Ghost

MOTOKO's instruments are shells. The ghost is not in any of them.

This is a citation of a problem: a named work is used as an epistemological
anchor, not as a character to play and not as artwork to copy. The works:
Shirow Masamune《攻殻機動隊》, Oshii Mamoru *Ghost in the Shell* (1995),
*Innocence* (2004), *Stand Alone Complex*.

## The ghost problem

In that corpus a body can be entirely prosthetic. Limbs, organs, even the
cyberbrain are replaceable inventory. What remains in question is the **ghost**
— whether a self is present, or only a well-organized shell that talks.

Three claims from that problem are useful here. They are structural, not
cosplay.

1. **A complete set of parts is not a person.** Replacing every prosthesis
   still leaves the Theseus question. Assembling Hermes, Strix, Nuclei,
   Kali, and recon scanners in one directory does not produce an agent. It
   produces inventory. Naming the IM surface Motoko does not either.
2. **Copies without an original still cohere.** Stand Alone Complex: a pattern
   can act without a master copy. A MOTOKO run is that kind of pattern — nodes
   firing in a graph — not a single canonical binary named Motoko.
3. **The ghost, if it exists, is not stored in a prosthesis.** You will not
   find it in `vendor/`. You will not find it in a skill file. It is the
   remainder after every replaceable part has been named.

MOTOKO's ghost is the remainder no instrument repo can hold: scope, interrupt,
evidence, and the human on IM.

## Shells (prosthetic repos)

Each cited repository is a shell. Shells are replaceable. Authority stays in
the shell's own license and release cycle. Citations point at **upstream**.
See [INSTRUMENTS.md](INSTRUMENTS.md).

| Shell | What it is in the body |
|---|---|
| Hermes Agent | Operator-facing body. IM in, tools out. Not the ghost. |
| Operator profile | Persona, templates, motoko scheduler skill. Still a shell. |
| Strix | Offensive cognition that insists on proof. A specialist organ. |
| Nuclei | Reflex scan: templates against a surface. |
| ProjectDiscovery recon | Name/URL surface (subfinder, katana, httpx, and kin). |
| Kali playbooks | Hands: CLI over a controlled environment. |
| LangGraph | Connective-tissue *contract*. Organization of the prostheses. Still not the ghost. |

A "complete Motoko agent" is therefore **not a merge**. It is this citation
graph plus the run-time graph in [GRAPH.md](GRAPH.md). Every part lives in a
different upstream repo on purpose. This repository holds the ontology and
the contract. It does not hold the prostheses. The work is orchestration.

## Where the ghost is allowed to appear

Only at points that no shell owns:

- **Scope.** A scanner cannot authorize itself.
- **Interrupt.** Destructive edges stop for the operator. A prosthesis that
  cannot be refused has no ghost; it is just actuation.
- **Evidence.** Hashed facts, not a model's self-report that it "has a self".
- **The IM human.** Hermes is the mouth. The operator is not a node.

If those four are removed, what remains is a toolkit. That is the correct
degraded mode. MOTOKO without a ghost is still useful inventory. It must not
pretend to be a person.

## What this file refuses

- It does not reconstruct a copyrighted character, voice, or likeness.
- It does not treat "concept, not product" as a license to copy.
- It does not put Shirow/Oshii text, designs, or marks into this tree.
- It does not claim that graph orchestration *creates* a ghost. It claims that
  orchestration is the only layer where the *question* of a ghost is even
  well-posed.

The name MOTOKO remains a callsign. The ghost remains a problem. The
engineering is the graph.
